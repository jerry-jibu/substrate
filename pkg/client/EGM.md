# client

## Overview
The Kubernetes client machinery for Substrate's CRD types, entirely generated by code-generator (`client-gen`, `informer-gen`, `lister-gen`). Every `.go` file under this tree carries a `Code generated ... DO NOT EDIT` header; regenerate instead of editing. Provides the clientset, shared informer factories, and listers for the `ate/v1` types defined in `api/infra/k8s/ate/v1`.

## Subdirectories & Boundaries
- clientset: [./clientset/EGM.md](./clientset/EGM.md) - versioned `Clientset` with typed `ate/v1` CRUD clients, generated fakes, and the scheme registration.
- informers: [./informers/EGM.md](./informers/EGM.md) - `SharedInformerFactory` sharing one informer per `ate/v1` resource type.
- listers: [./listers/EGM.md](./listers/EGM.md) - indexer-backed listers for `CSIDriverConfig`, `SandboxConfig`, and `WorkerPool`.

## Invariants
- All code here is generator output; hand edits are overwritten. Change the API types or generator inputs instead (header on `clientset/versioned/clientset.go:15` and every other file).
- The exported surface tracks the CRDs in `api/infra/k8s/ate/v1`: the scheme builder is exactly `atev1.AddToScheme` (`clientset/versioned/scheme/register.go:localSchemeBuilder`).

## Side Effects
- The real (non-fake) clientset and informers perform HTTP list/watch/create/update/delete calls against the Kubernetes API server (`clientset/versioned/clientset.go:NewForConfig`); the fake trees stay in memory (`clientset/versioned/fake/clientset_generated.go:NewSimpleClientset`).
