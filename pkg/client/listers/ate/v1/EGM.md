# listers/ate/v1

## Overview
Listers for the `ate` API group, version `v1`, generated by `lister-gen` from the CRD types in `api/infra/k8s/ate/v1`. Every file in this directory carries a `Code generated ... DO NOT EDIT` header. A lister reads objects from a `cache.Indexer` filled by an informer; it never talks to the API server.

## Interface
- `CSIDriverConfigLister` with `List(selector)` and `Get(name)`; built by `NewCSIDriverConfigLister(indexer)` (`csidriverconfig.go:CSIDriverConfigLister`, `csidriverconfig.go:NewCSIDriverConfigLister`)
- `SandboxConfigLister` with `List(selector)` and `Get(name)`; built by `NewSandboxConfigLister(indexer)` (`sandboxconfig.go:SandboxConfigLister`, `sandboxconfig.go:NewSandboxConfigLister`)
- `WorkerPoolLister` with `List(selector)` and `WorkerPools(namespace)`, returning a `WorkerPoolNamespaceLister` with namespaced `List`/`Get`; built by `NewWorkerPoolLister(indexer)` (`workerpool.go:WorkerPoolLister`, `workerpool.go:WorkerPoolNamespaceLister`, `workerpool.go:NewWorkerPoolLister`)
- Expansion marker interfaces for custom methods: `CSIDriverConfigListerExpansion`, `SandboxConfigListerExpansion`, `WorkerPoolListerExpansion`, `WorkerPoolNamespaceListerExpansion` (`expansion_generated.go`)

## Invariants
- Objects returned by every lister must be treated as read-only (`workerpool.go:WorkerPoolLister` doc comment; same wording on `csidriverconfig.go:CSIDriverConfigLister` and `sandboxconfig.go:SandboxConfigLister`).
- Listers read only from the `cache.Indexer` passed to their constructors; freshness is the informer's responsibility (`workerpool.go:NewWorkerPoolLister`).

## Side Effects
- None.
