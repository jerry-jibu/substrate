# ate/v1 (Kubernetes CRD types)

## Overview

Go types for the `ate.dev/v1` Kubernetes API group: the `WorkerPool`,
`SandboxConfig`, and `CSIDriverConfig` custom resources. The hand-written
files are the contract; `zz_generated.deepcopy.go` is generated by
controller-gen, and `gen.go` drives CRD and client codegen into
`manifests/ate-install/generated/` and `pkg/client/`. Go package:
`go.ate.dev/substrate/api/infra/k8s/ate/v1` (package `v1`).

## Interface

- `WorkerPool` + `WorkerPoolSpec` + `WorkerPoolStatus`
  (`workerpool_types.go:267`, `:88`, `:171`): namespaced resource
  (`+kubebuilder:resource:scope=Namespaced`) defining worker replicas,
  `workerImage`, optional `WorkerPoolPodTemplate`, and exactly one
  `WorkerPoolSandboxClass` entry.
- `WorkerPoolSandboxClass` and `SandboxConfigReference`
  (`workerpool_types.go:117`, `:138`): bind the pool to a cluster-scoped
  `SandboxConfig` by name or the annotated class default.
- Methods: `(*WorkerPoolSpec).DefaultSandboxClass()` and
  `(*WorkerPool).ResolvedSandboxConfig()` (`workerpool_types.go:150`,
  `:161`).
- Condition and reason constants: `WorkerPoolSandboxClassConditionResolved`,
  `WorkerPoolReasonSandboxConfigNotFound`, `WorkerPoolReasonSandboxConfigDeleting`,
  `WorkerPoolReasonSandboxClassMismatch`, `WorkerPoolReasonDefaultConfigNotFound`
  (`workerpool_types.go:229`-`:251`).
- `SandboxConfig` + `SandboxConfigSpec` + `SandboxVersionConfig` +
  `AssetFile` (`sandboxconfig_types.go:194`, `:135`, `:101`, `:37`):
  cluster-scoped resource describing per-architecture sandbox runtime assets
  keyed by version name.
- `SandboxClass` type with `SandboxClassGvisor` and `SandboxClassMicroVM`
  (`sandboxconfig_types.go:25`-`:33`); method
  `(*SandboxConfigSpec).DefaultVersionConfig()` (`sandboxconfig_types.go:167`).
- Annotations and finalizers: `SandboxConfigClassDefaultAnnotation`
  (`sandboxconfig.ate.dev/is-class-default`) and
  `SandboxConfigWorkerPoolProtectionFinalizer`
  (`sandboxconfig.ate.dev/workerpool-protection`)
  (`sandboxconfig_types.go:62`, `:84`).
- `CSIDriverConfig` + `CSIDriverConfigSpec` + `CSIDriverTLSConfig`
  (`csidriverconfig_types.go:81`, `:22`, `:55`): cluster-scoped resource
  naming a CSI driver, its controller gRPC endpoint, node socket override,
  and optional pod-identity TLS.
- Scheme registration: `GroupVersion`, `SchemeBuilder`, `AddToScheme`,
  `Resource` (`groupversion_info.go:27`-`:41`); each type registers itself in
  `init()` (`workerpool_types.go:292`, `sandboxconfig_types.go:215`,
  `csidriverconfig_types.go:102`).

## Invariants

- `WorkerPoolSpec.SandboxClasses` holds exactly one entry and its name is
  immutable after creation (`workerpool_types.go:104`-`:113`).
- `metadata.name` of a `WorkerPool` is at most 63 characters because worker
  pods use it as a label value (`workerpool_types.go:266`).
- Label and annotation keys in `ate.dev` and its subdomains are reserved for
  controllers on `WorkerPoolPodTemplate` (`workerpool_types.go:38`, `:47`).
- `SandboxConfigSpec.DefaultVersion` must name an existing version and that
  version must not be `Disabled` (`sandboxconfig_types.go:133`-`:134`);
  `DefaultVersionConfig` never returns a Disabled entry
  (`sandboxconfig_types.go:163`-`:166`).
- The `workerpool-protection` finalizer keeps a `SandboxConfig` terminating
  until no `WorkerPool` status names it in `configRef` or `pendingConfigRef`
  (`sandboxconfig_types.go:64`-`:84`).
- `AssetFile.SHA256` must be 64 lower-case hex characters and both names the
  cached file and verifies the download (`sandboxconfig_types.go:51`-`:56`).
- When `CSIDriverTLSConfig.Enabled` is true, `usePodIdentity` must be true
  and `serverName` must be set; manual certificates are not supported
  (`csidriverconfig_types.go:53`-`:54`).
- `CSIDriverConfigSpec.ControllerEndpoint` must match `tcp://` or `dns://`
  (`csidriverconfig_types.go:37`).

## Side Effects

- The `init()` functions register the CRD types into `SchemeBuilder`, so
  importing the package extends any `runtime.Scheme` that applies
  `AddToScheme` (`workerpool_types.go:292`, `sandboxconfig_types.go:215`,
  `csidriverconfig_types.go:102`).
- The `//go:generate` directives in `gen.go` write generated CRDs, clientsets,
  listers, and informers outside this directory when codegen runs
  (`gen.go:17`-`:20`).
