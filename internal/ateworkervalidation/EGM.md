# ateworkervalidation

## Overview
Declarative validation for the Worker RPC surface, generated by Kubernetes validation-gen from `internal/proto/ateworkerpb` plus hand-written custom rules. A separate package because both worker binaries (ateworker-gvisor and ateworker-microvm) implement the service in package main and share one set of rules (`doc.go`).

## Interface
- `validate.go:ValidateRunWorkloadRequest`, `ValidateCheckpointWorkloadRequest`, `ValidateRestoreWorkloadRequest`, `ValidateTerminateWorkloadRequest`, `ValidateGetWorkloadStatsRequest` - RPC-edge validators.
- `validate.go:ValidateCustom_EgressGateway_Address`, `ValidateCustom_HttpGetAction_Path`, `ValidateCustom_VolumeMount_MountPath`, `ValidateCustom_Container`, `ValidateCustom_ActorDirs` - custom rules invoked by the generated code.
- `zz_generated.validation.go` - generated per-field validation for `*Request` types.

## Invariants
- Requests are validated as creates: no Worker RPC updates prior state, so there is nothing to ratchet against (`validate.go` package comment).
- A validation failure becomes the `InvalidArgument` error the handler responds with, built by `resources.ToAPIError` (`validate.go` package comment).
- The custom rules reuse atelet's shared rules through `internal/resources` so both ends of the RPC agree on what is dialable and mountable (`validate.go:ValidateCustom_EgressGateway_Address`).
- `ValidateCustom_Container` holds mount paths unique and non-nesting across a container's mount lists; volumes cannot mount onto other volumes (`validate.go:ValidateCustom_Container`).

## Side Effects
- None. Pure request validation.
